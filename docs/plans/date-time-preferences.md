# Date and time preferences

Status: implemented and verified locally on 17 September 2026.

## Requirements and implementation

- Store date format, time format, and IANA time zone per user. Keep the existing short-month date and 24-hour time as defaults.
- Add Preferences under My Settings / Account, with predefined formats, searchable time zones, a server-rendered preview, and save feedback.
- Retain machine timestamps in every response. Include a documented `localization` object containing the effective preferences and server-rendered labels keyed by the original timestamp.
- Browser sessions and personal keys use the current user's saved preferences; team keys use default formatting in UTC. Never accept an owner ID from a preferences request.
- MCP tool results expose the same localization contract after composing their results. Streaming records also carry their localized labels.
- UI display helpers read server labels. Relative-time calculations, chronology, filtering, and elapsed durations remain client calculations. Absolute dates, chart ticks, log prefixes, tooltips, and date-picker display values must not be formatted in the browser.
- Changing preferences invalidates cached responses; late responses from before the save must not restore the old labels. Clear private localization data on sign-out or user changes.
- Custom monitoring ranges must interpret wall-clock input using the selected time zone on the server, including DST validation.
- Update the fresh v2 initial schema, fixtures, API/OpenAPI/MCP contracts, and documentation.

Protocol boundaries: Better Auth's own authentication/WebAuthn wire formats, raw log contents and 204 responses keep their existing contracts. Dashboard passkey dates are exposed through the localized personal metadata endpoint. Date-only aggregation buckets remain calendar dates and do not shift across time zones. Original machine timestamps remain the source for sorting, cursors, filters and duration calculations.

Cache checks: changing preferences clears response and label caches; generation checks reject late responses from the previous preference set or signed-out account. The browser verified that changing to 24-hour format in another tab refreshed an already-open monitoring table to `01:03, 2026-09-17`, then verified saving the original review format again. Invalid time-zone search text did not replace the saved selection.

Responsive review: checked the preferences widget at desktop width and 390px mobile width. Controls stack on mobile; the document width remained 390px with no horizontal overflow. Selects use the secondary surface variant. Browser console error collections were empty on Preferences and deployment logs.
