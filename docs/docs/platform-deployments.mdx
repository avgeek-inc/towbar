---
title: "Deployment modes"
description: "Deploy Dockerfiles, static sites, OCI images, Railpack, Nixpacks, Buildpacks, and Compose projects."
---

Towbar reads deployment configuration from the Git revision being deployed. The
dashboard validates and operates that declaration; it does not keep a second
workload configuration.

## Choose a mode

| Mode         | Use it for                                    |
| ------------ | --------------------------------------------- |
| `dockerfile` | An existing Dockerfile                        |
| `static`     | Prebuilt or generated browser assets          |
| `image`      | An image built elsewhere                      |
| `railpack`   | Recommended source detection                  |
| `nixpacks`   | Compatibility with existing Nixpacks projects |
| `buildpack`  | Cloud Native Buildpacks                       |
| Compose      | A multi-service project                       |

Every app selects its mode under `deployment`. This Dockerfile app builds only
the `apps/api` directory:

```yaml title=".towbar/apps/api.app.yml" highlight={3-6}
id: api
name: API
deployment:
  type: dockerfile
  context: apps/api
  dockerfile: apps/api/Dockerfile
container:
  port: 3000
environments:
  production:
    server: 192.0.2.10
```

Paths stay inside the declared context. Build tools and builder images that the
manifest accepts must be pinned to an immutable digest. See
`examples/platform-modes` in the Towbar repository for one validated entity
file per mode.

## Configure a source build

Source builders share fields for context, commands, architecture, timeouts,
build arguments, resource limits, and cache policy. Add only the fields your
builder needs:

```yaml title=".towbar/apps/web.app.yml" highlight={3-9}
id: web
name: Web
deployment:
  type: dockerfile
  context: apps/web
  dockerfile: apps/web/Dockerfile
  architecture: amd64
  cache:
    enabled: true
container:
  port: 8080
environments:
  production:
    server: 192.0.2.10
```

Dockerfile and static builds can receive protected build values through their
secret-safe paths. Railpack, Nixpacks, and Buildpacks reject build secrets so a
credential cannot be retained in an image layer or shared cache. Use a
Dockerfile when the build itself needs credentials.

Cancellation stops the active command and removes staged source and unpromoted
images. A cache belongs to the workload unless you set an authorized shared
`cache.scope`. Inactive cache scopes are reclaimed after 30 days.

## Prebuilt images

Set `type: image` and use an explicit tag or digest. Add `registry` only for a
private image:

```yaml title=".towbar/apps/worker.app.yml" highlight={3-6}
id: worker
name: Worker
deployment:
  type: image
  image: registry.example.com/acme/worker:2.4.0
  registry: registry
container:
  port: 3000
environments:
  production:
    server: 192.0.2.10
```

Towbar resolves a tag to an immutable digest before execution. `latest` is
rejected, and a changed digest fails the deployment. Private registries require
HTTPS; private-network access must be enabled on the integration when needed.

## Build servers

Set `buildServer` in `towbar.yml` to use one prepared server for every app in an
environment. `direct` streams the verified image archive to the runtime server:

```yaml title="towbar.yml" highlight={2-5}
version: 2
buildServer:
  ip: 192.0.2.20
  transfer: direct
  allowRuntimeFallback: false
environments:
  production: {}
```

An environment or app can override the default. Use `null` when one app should
build on its runtime server:

```yaml title=".towbar/apps/worker.app.yml" highlight={3}
id: worker
name: Worker
buildServer: null
deployment:
  type: dockerfile
  context: apps/worker
  dockerfile: apps/worker/Dockerfile
container:
  port: 3000
environments:
  production:
    server: 192.0.2.10
```

For registry transfer, set `transfer: registry` and add the enabled registry
integration name. The build server must belong to the team, have trusted SSH
credentials, be prepared, and support the requested architecture. Without
`allowRuntimeFallback: true`, an unavailable build server fails closed.

Compose projects always build on their runtime server because Compose resolves
the service graph as one project.

## Rolling and recreate strategies

Stateless apps default to health-gated rolling replacement. Configure only the
limits that differ from the defaults:

```yaml title=".towbar/apps/api.app.yml" highlight={3-8}
id: api
name: API
rollout:
  type: rolling
  replicas: 2
  maxSurge: 1
  maxUnavailable: 0
  minimumHealthySeconds: 15
container:
  port: 3000
environments:
  production:
    server: 192.0.2.10
```

Use `recreate` for a single-writer volume, fixed host port, or another workload
that cannot run two releases together:

```yaml title=".towbar/apps/files.app.yml" highlight={3-6}
id: files
name: Files
rollout:
  type: recreate
  maintenanceMode: true
  reason: The app uses a single-writer volume
container:
  port: 3000
environments:
  production:
    server: 192.0.2.10
```

Rolling admission checks capacity before replacement and promotes only after
the candidate stays healthy. App rollback selects an earlier image; it does not
reverse a database migration or restore persistent data.

## Compose projects

Put each Compose workload under `.towbar/compose`. The entity points to the
repository-owned Compose files and declares only Towbar's public service policy:

```yaml title=".towbar/compose/storefront.compose.yml" highlight={3-13}
id: storefront
name: Storefront
file: deploy/compose.yml
overrides:
  - deploy/compose.production.yml
profiles: [production]
strategy: maintenance
services:
  web:
    port: 3000
    domains: [store.example.com]
    ingress:
      type: proxy
  cache: {}
environments:
  production:
    server: 192.0.2.10
```

Towbar validates the resolved Compose project before Docker opens it. Local
includes and `extends` files must stay inside the immutable checkout. Remote
includes, privileged containers, Docker socket mounts, host bind mounts,
devices, public host ports, and external or explicitly named Docker resources
are rejected. Compose replacement uses `recreate` or `maintenance`; rolling
Compose replacement is not supported.

## Reference an integration

Manifest fields use the stable runtime names shown on the Integrations pages.
For example, `registry: registry` selects the configured OCI registry and
`telemetry.integration: otlp` selects OpenTelemetry. Repository sync and queued
execution both verify that the provider is still enabled and supports the
requested capability.
