AWS is optional. Enable it only when a datastore backup policy uses AWS S3.

## Prepare AWS access

Create a bucket and an IAM identity for Towbar's backup work. Scope object listing, upload, read, and deletion to the buckets and prefixes in your datastore policies; include object-version and KMS permissions when those features are used. Record the bucket's region. Towbar uses a static access-key pair in its protected runtime configuration; temporary AWS sessions are not supported.

```yaml title="/etc/towbar/config.yml"
integrations:
  aws:
    enabled: true
    region: us-east-1
    accessKeyId: <access-key-id>
    secretAccessKey: <secret-access-key>
```

Run `sudo towbar config validate` and `sudo towbar restart`.

Towbar shows AWS only when all enabled values pass startup validation and never returns the credential in the UI or API.

## Verify backup and restore

Set a managed Datastore's [backup policy](/docs/backups) to use `aws`, create a backup, and inspect the saved object's verification state. Perform a [fresh-target restore](/docs/restores) before treating the destination as recovery-ready. A **Configured** chip means YAML validation succeeded; it does not prove S3 or KMS access.

If a run fails, check its final stage, region, bucket and prefix, key permissions, object versioning, and KMS policy. Rotate the key in `config.yml`, restart Towbar, verify a backup and restore path, and then retire the old key.
