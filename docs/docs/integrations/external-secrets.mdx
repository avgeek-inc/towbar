---
title: "External secrets"
description: "Choose Infisical or Doppler and reference values without committing them to Git."
---

Towbar supports two external-secret integrations: [Infisical](/docs/integrations/infisical) with a machine identity and [Doppler](/docs/integrations/doppler) with a service token. Each has its own setup guide. Provider credentials stay in `/etc/towbar/towbar.yml`; workload manifests contain references rather than values.

The manifest key is the variable presented to the workload. A reference selects the provider integration, secret location, optional field or version, and build or runtime stage. Towbar resolves it during deployment, not during repository sync.

```yaml title=".towbar/apps/api.app.yml"
externalSecrets:
  API_TOKEN:
    integration: infisical
    secret: /production/api-token
    use: runtime
```

Apps, resources, and Compose projects can use runtime references. Dockerfile and static apps can use build references through their protected build path; other builders reject build secrets. A provider appearing as **Configured** proves only local configuration validity. Deploy a non-production reference to verify its remote permissions, then read [Shared and workload secrets](/docs/secrets#external-secret-providers) for value precedence and failure handling.
