Create a bot in Telegram and keep its bot token in Towbar's protected YAML file. Add the bot to each target chat and grant it permission to post. A destination uses a numeric chat ID and, for a forum topic, an optional numeric Topic ID. One chat can have separate rows for different topics.

```yaml title="/etc/towbar/config.yml"
notifications:
  enabled: true
  providers:
    telegram:
      botToken: "123456:<bot-token>"
```

Run `sudo towbar config validate` and `sudo towbar restart`. Open **Manage → Notifications → Telegram**, add a chat ID, and leave Topic ID blank for the main chat. Choose **All** or **Failures only** for deployments, and select **Backup & Restore** and **Incidents** separately. New rows have no categories selected; changes save immediately.

## Verify and troubleshoot

Use **Test** and confirm that the sample appears in the right chat or topic. If it fails, check the bot token, the numeric IDs, bot membership, and posting permissions. A topic ID used for a different chat cannot route the message. Inspect the [delivery result](/docs/integrations/notifications#delivery-history) for provider errors and retry status.

Service and datastore manifests can declare extra Telegram chat/topic destinations without storing the bot token. See [manifest notification routing](/docs/integrations/notifications#route-events-for-one-workload). Rotate the bot token in YAML, restart, and test before discarding the old token.
