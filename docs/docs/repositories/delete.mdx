---
title: "Delete a repository"
description: "Review what Towbar removes, what keeps running, and how to clean up a server."
---

Delete a Repository only after reviewing its services, datastores, environments, and active operations. Removing the connection deletes its imported inventory and operational history from Towbar. It does not stop containers or erase Docker data on a server.

## Before deletion

1. Record any environment branch mappings or manifest IDs you may need later.
2. Allow active deployments and resource operations to finish.
3. Arrange separate protection for persistent data. Repository deletion is not a database restore or volume-backup operation.

After deletion, open each affected server and run **Check server**. Under **Settings → Cleanup**, review leftover containers, images, and volumes. Towbar checks ownership and current references again before removing selected objects. Volume removal is a separate permanent choice; it never happens automatically as a side effect of deleting a repository.

If you intend to keep operating the workloads, leave the repository connected or plan a migration before deletion. [Server cleanup](/docs/servers/operations#clean-up-leftover-workloads) explains the host-side boundary in more detail.
