**Upstream source:** [Current installation guide](https://forgejo.org/docs/latest/admin/installation/docker/).

The Compose file itself must be committed at the path in the manifest. This page shows Towbar's declaration, not an invented upstream Compose specification. Match the actual service name and internal port when adapting the upstream file.

## Towbar manifest

```yaml title=".towbar/services/forgejo.compose.yml"
id: forgejo
name: Forgejo
file: deploy/forgejo/compose.yml
strategy: maintenance
services:
  server:
    port: 3000
    domains:
      - forgejo.example.com
    ingress:
      type: proxy
environments:
  production:
    server: 192.0.2.10
```

## Configure

1. Register and prepare the example server, connect the repository, and map `production` to the branch containing these files.
2. Copy the current [upstream installation](https://forgejo.org/docs/latest/admin/installation/docker/) into the repository at `deploy/forgejo/compose.yml`. Pin its images, match the Compose service name shown above, and adapt mounts, ports, and networks to [Towbar's Compose restrictions](/docs/services/modes/compose).
3. Supply the software's own required environment values and persistent storage according to its upstream guide. A valid Towbar manifest does not make an unadapted upstream Compose file deployable.
4. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Preserve `/data` and plan SSH access separately from HTTP routing.

For exact field constraints, consult the [Service manifest](/docs/services/manifest), [Datastore manifest](/docs/datastores/manifest), or [Compose guide](/docs/services/modes/compose) that applies to this example.
