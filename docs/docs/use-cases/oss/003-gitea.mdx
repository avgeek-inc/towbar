**Upstream source:** [Current installation guide](https://docs.gitea.com/next/installation/install-with-docker/).

The Compose file itself must be committed at the path in the manifest. This page shows Towbar's declaration, not an invented upstream Compose specification. Match the actual service name and internal port when adapting the upstream file.

## Towbar manifest

```yaml title=".towbar/services/gitea.compose.yml"
id: gitea
name: Gitea
file: deploy/gitea/compose.yml
strategy: maintenance
services:
  server:
    port: 3000
    domains:
      - gitea.example.com
    ingress:
      type: proxy
environments:
  production:
    server: 192.0.2.10
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Copy the current [upstream installation](https://docs.gitea.com/next/installation/install-with-docker/) into the repository at `deploy/gitea/compose.yml`. Pin its images, match the Compose service name shown above, and adapt mounts, ports, and networks to [Towbar's Compose restrictions](/docs/services/modes/compose).
3. Supply the software's own required environment values and persistent storage according to its upstream guide. A valid Towbar manifest does not make an unadapted upstream Compose file deployable.
4. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Preserve `/data`; web routing does not by itself expose Git-over-SSH.

For field constraints, see [Compose guide](/docs/services/modes/compose).
