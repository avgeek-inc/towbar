**Upstream source:** [Current installation guide](https://jellyfin.org/docs/general/installation/container/).

The Compose file itself must be committed at the path in the manifest. This page shows Towbar's declaration, not an invented upstream Compose specification. Match the actual service name and internal port when adapting the upstream file.

## Towbar manifest

```yaml title=".towbar/services/jellyfin.compose.yml"
id: jellyfin
name: Jellyfin
file: deploy/jellyfin/compose.yml
strategy: maintenance
services:
  jellyfin:
    port: 8096
    domains:
      - jellyfin.example.com
    ingress:
      type: proxy
environments:
  production:
    server: 192.0.2.10
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Copy the current [upstream installation](https://jellyfin.org/docs/general/installation/container/) into the repository at `deploy/jellyfin/compose.yml`. Pin its images, match the Compose service name shown above, and adapt mounts, ports, and networks to [Towbar's Compose restrictions](/docs/services/modes/compose).
3. Add persistent configuration, cache, and media volumes in the upstream Compose file. This example covers HTTP access; DLNA, host networking, and hardware transcoding need capabilities outside this manifest.
4. Supply the software's own required environment values and persistent storage according to its upstream guide. A valid Towbar manifest does not make an unadapted upstream Compose file deployable.
5. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

The HTTP app listens on port 8096. DLNA, host networking, and hardware transcoding need separate platform capabilities.

For field constraints, see [Compose guide](/docs/services/modes/compose).
