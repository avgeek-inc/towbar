## Towbar manifest

```yaml title=".towbar/services/uptime-kuma.service.yml"
id: uptime-kuma
name: Uptime Kuma
buildServer: null
deployment:
  type: image
  image: louislam/uptime-kuma:2
  platform: linux/amd64
container:
  port: 3001
  volumes:
    - name: data
      mountPath: /app/data
      initialData: image
health:
  path: /
environments:
  production:
    server: 192.0.2.10
rollout:
  type: recreate
  maintenanceMode: true
  reason: Single-writer data volume
domains:
  primary: uptime-kuma.example.com
tls:
  mode: direct
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Use local storage with POSIX file locking; keep a separate copy of the Service volume.

For field constraints, see [Service manifest](/docs/services/manifest).
