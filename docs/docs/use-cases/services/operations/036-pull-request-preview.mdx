---
title: "Pull-request preview"
description: "Enable previews in root towbar.yml, then set the Service preview block."
---

**Related reading:** [Previews](/docs/previews).

`context: .` means the repository root. The source project, start command, and health endpoint must match the selected build mode.

## Towbar manifests

```yaml title="towbar.yml"
version: 2
environments:
  production:
    previews:
      enabled: true
```

```yaml title=".towbar/services/pull-request-preview.service.yml"
id: pull-request-preview
name: Pull-request preview
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
preview:
  enabled: true
  domain: preview.example.com
  ttlHours: 72
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Configure preview DNS and isolated preview secrets, then verify a pull request creates a separate preview workload.
3. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Preview secrets are isolated and the preview domain resolves.

For field constraints, see [Service manifest](/docs/services/manifest).
