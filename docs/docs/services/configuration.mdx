title: "Container and health"
description: "Set the Service port, capacity, private network, persistent volumes, and readiness check."
---

The `container` block describes how the deployed image runs. `port` is the port **inside** the container; the process must listen on the container's network interface. Set resource limits near the port so a reviewer can assess expected capacity:

```yaml title=".towbar/services/web.service.yml"
container:
  port: 3000
  resources:
    cpus: 1
    memory: 1g
health:
  path: /health
  timeoutSeconds: 60
```

The HTTP health path should respond without interactive authentication. A successful build is not sufficient for traffic promotion: Towbar waits for the candidate to pass readiness. Allow enough time for startup, but investigate a consistently slow start rather than raising the timeout indefinitely.

## Private connectivity

Set the same `container.network` on a Service and Datastore on the same server. A Datastore's ID is its network alias unless it sets `networkAlias`:

```yaml title=".towbar/services/web.service.yml"
container:
  port: 3000
  network: application
```

For a PostgreSQL datastore with alias `postgres`, the Service can connect to `postgres:5432`. Put the credential-bearing URL in a [service runtime secret](/docs/secrets), not in the manifest. A Docker network on one host does not connect containers across different servers.

## Persistent storage

Use a Docker-managed named volume when a process must retain files across replacement:

```yaml title=".towbar/services/files.service.yml"
rollout:
  type: recreate
  maintenanceMode: true
  reason: The service uses a single-writer volume
container:
  port: 3000
  volumes:
    - name: uploads
      mountPath: /app/uploads
      initialData: image
```

Create the mount directory in the image with ownership for its runtime user. Volumes survive redeployments and image rollback, remain on their server, and are not backed up by Towbar. `initialData` applies only when adding a new volume: `previous-container` imports from the stopped container, while `image` initializes from the new image. Environment overrides replace the common volume list. Host-directory bind mounts are not accepted; keep backups of important files outside Towbar.

## Docker host logs

A trusted log collector Service can request one fixed, read-only host mount. First, an Admin must enable **Allow Docker log collection** under the target server's **Settings → Configuration**. Then declare `container.hostLogs.dockerJsonFiles: true`:

```yaml title=".towbar/services/host-logs.service.yml"
id: host-logs
name: Host logs
deployment:
  type: dockerfile
  context: observability/fluent-bit
  dockerfile: observability/fluent-bit/Dockerfile
rollout:
  type: recreate
  maintenanceMode: true
  reason: One collector writes the persistent cursor and buffer
container:
  port: 2020
  resources:
    cpus: 0.25
    memory: 256m
  hostLogs:
    dockerJsonFiles: true
  volumes:
    - name: state
      mountPath: /var/lib/fluent-bit
      initialData: image
health:
  path: /api/v1/health
  timeoutSeconds: 60
environments:
  production:
    server: 192.0.2.10
```

Towbar reads `DockerRootDir` from the target daemon and mounts its `containers` directory at `/var/lib/docker/containers`. A custom Docker data directory is supported. The manifest cannot choose a host path, make this mount writable, or attach a Docker socket. Named volumes must not overlap the log mount. Compose workloads, deployment hooks, and scheduled jobs do not receive this capability, and collectors cannot enable Previews.

<Warning>
  This mount exposes logs and container metadata for every container on the
  server, including workloads outside the collector's Repository. Those files
  can contain credentials and private data. Only deploy collector images and
  configuration you trust with that access.
</Warning>

The collector runs as UID/GID `0:0` with all Linux capabilities dropped, `no-new-privileges`, a read-only root filesystem, and a 16 MiB temporary `/tmp`. This requires rootful Docker without user namespace remapping. Towbar creates an owned `local` driver volume with fixed `bind,ro,private` options, checks its source and ownership before startup, and mounts it read-only with private propagation. Existing and future host submounts are excluded. The CPU and memory limits and persistent named storage are required; the example's 0.25 CPU and 256 MiB are a starting budget. Measure consumption and set a bounded on-disk buffer in the collector configuration. Collector runtime secrets cannot override Docker connection settings such as `DOCKER_HOST` or `DOCKER_CONTEXT`.

For Fluent Bit, tail `/var/lib/docker/containers/*/*-json.log`, keep the Tail database and filesystem buffer under `/var/lib/fluent-bit`, and enable its HTTP server and health check on `0.0.0.0:2020`. See the [Tail input](https://docs.fluentbit.io/manual/data-pipeline/inputs/tail), [buffering](https://docs.fluentbit.io/manual/administration/buffering-and-storage), and [health check](https://docs.fluentbit.io/manual/administration/monitoring#health-check-for-fluent-bit) configuration. Towbar preserves the volume across replacement and requires a maintenance rollout so two collector versions cannot write it together.

Towbar uses Docker's `local` logging driver for the collector itself, with rotation capped at three 10 MiB files. Its output is therefore excluded from the `*-json.log` glob without a container-ID exclusion rule. Other containers must use `json-file` to appear in that glob; this capability does not collect journald, `local`, or remote-driver logs.

API keys need edit access with administrative operations enabled and explicit `deployment.create` and `server.collectLogs` grants. Towbar checks authority at admission and again when a queued deployment starts, including rollback to a retained collector image. It also checks the server's current opt-in. Disabling the setting prevents further collector deployments; stop and remove existing collector containers to revoke their mounted access. Changing the setting does not unmount or stop a running container.
