---
title: "Shared secrets"
description: "Reuse workspace values through explicit references."
---

Open **Manage → Shared secrets** to save workspace-wide values for Build, Runtime, Pre-deploy, or Post-deploy. These values are shared across environments at the selected stage, so use separate keys when production and staging need different credentials.

Shared values are **not** automatically added to apps or resources. Declare each workload key in its manifest, then save a reference in the corresponding workload stage:

```yaml title=".towbar/apps/api.app.yml"
secrets:
  runtime:
    - API_TOKEN
    - AUTH_HEADER
```

```text title="App → Settings → Secrets → Runtime"
API_TOKEN="{{globals.API_TOKEN}}"
AUTH_HEADER="Bearer {{globals.API_TOKEN}}"
```

Both examples read `API_TOKEN` from the workspace Runtime stage. The reference may form the whole value or appear inside a larger string. A missing or invalid reference stops deployment without printing its value. Shared values themselves are literal and do not resolve further references.

Only an authorized Admin can reveal a saved value. Use **Form** for individual keys or **Editor** for `KEY=value` lines. Saving a shared value affects the next execution of every workload that references it; redeploy consumers to update running processes. Changing a shared value does not queue those deployments automatically.
