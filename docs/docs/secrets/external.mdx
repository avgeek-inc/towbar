---
title: "External secrets"
description: "Import runtime variables from an Infisical folder or Doppler config."
---

First configure an [Infisical](/docs/integrations/infisical) machine identity or [Doppler](/docs/integrations/doppler) service token in Towbar. Its credentials stay in the protected Towbar configuration. A workload manifest selects the external scope without containing secret values. Towbar reads the selected secrets at deployment and passes them to the running workload under their provider key names.

## Infisical project and folder

Use the Infisical project ID. `environment` and `secretPath` are optional. With both omitted, Towbar reads the `prod` environment root (`/`). `Production` is accepted as an alias for the default `prod` slug; use the slug for custom environments.

```yaml title=".towbar/resources/postgres.resource.yml"
externalSecrets:
  integration: infisical
  project: 6354f023-12c7-4ce1-b860-750b38e1a3ef
  environment: Production
  secretPath: infisical-postgres
```

This imports every secret directly inside `/infisical-postgres`. It does not recursively import child folders. To use the root explicitly, set `secretPath: .`. The integration's machine identity must have read access to that project, environment, and folder.

## Doppler project and config

Doppler identifies a project by its slug. Its `environment` field selects a **config name**, such as `prd`. A Doppler service token is bound to one config; when you omit `environment`, Towbar uses the token's config. Doppler does not have an Infisical-style `secretPath` folder, so omit that field.

```yaml title=".towbar/apps/api.app.yml"
externalSecrets:
  integration: doppler
  project: example-api
  environment: prd
```

This imports all secrets in `example-api`'s `prd` config. To use the config bound to the service token, omit `environment`:

```yaml title=".towbar/apps/api.app.yml"
externalSecrets:
  integration: doppler
  project: example-api
```

## Required names and failures

You can also declare required names under `secrets.runtime`. Towbar checks the combined Towbar-managed and external values before starting the workload. A missing required name, duplicate name across the two sources, inaccessible provider, empty scope, or changed secret snapshot stops deployment. Values are fetched again for execution, and a changed or disappeared secret fails closed.

The source block imports **runtime** values for apps, resources, and Compose workloads. External values are not injected into builds or deployment hooks. Save those stage values in [workload secrets](/docs/secrets/workload) or reference [shared secrets](/docs/secrets/shared). Keep provider tokens out of repositories, limit each identity to its intended project or config, and deploy a non-production workload to verify access before relying on it in production.
