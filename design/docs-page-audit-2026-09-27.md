# Documentation page audit — 2026-09-27

This checklist covers every current Markdown/MDX page, including generated API operations. For each page, verify: factual correctness against the current code and UI; opportunities to simplify or expand; plain language and agent readability; examples where useful; screenshots where useful; working internal and external links; and whether a focused companion page is needed. Check a page only after all seven questions have been reviewed.

Site-wide link sweep: all 249 pages returned HTTP 200 on the local Mintlify preview; all 87 distinct external links in product guides returned HTTP 200 during this audit. `pnpm docs:check` checks metadata, navigation, internal links and screenshot assets. The 137 generated API pages were checked as a group against the current 199 route handlers and OpenAPI export with `pnpm docs:api:check`. Their request/response examples come from that specification; product screenshots are not useful on operation reference pages. These checks support but do not replace the prose review of authored guides.
Inventory: **249/249 pages reviewed** (106 guides, 137 generated API operations, and 6 other pages).

## Findings and decisions

- Replaced links to JSON Schemas under `/schemas/`, which the local Mintlify preview returned as 404, with stable raw GitHub links to the generated schemas. The docs checker now rejects unpublished local asset routes.
- Checked every authored page for current terminology and edited stale Service/Datastore, server-credential, secret, health-check, and runtime-configuration descriptions. The API and MCP reference retain legacy route and `kind` identifiers only where they are part of the actual wire contract; the overview maps those identifiers to the dashboard terms.
- Validated all published YAML examples against the current parser, regenerated the API reference from the route implementation, and refreshed the release screenshots in both themes. A rendered-page review confirmed the screenshots stay within the article column and the configuration guide's command blocks render correctly.
- The repository, server, service, datastore, engine, secrets, integration, operation, and self-hosting topics already have focused companion pages. Migration comparisons use destination tables and link to the full Service and Datastore examples instead of repeating fragile snippets for each source platform. API operation pages use request/response examples; screenshots would not clarify their contracts.
